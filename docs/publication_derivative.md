# Publication derivatives of recorded measurements

A publication repair can change layout without making a new measurement. The
normal network claim validator still authenticates the complete source inventory
recorded in each original receipt. A changed figure module intentionally fails
that strict check. Neither the recorder writer nor the validator silently
accepts a different source tree.

The explicit publication derivative contract keeps two identities: the original
measurement source reconstructed from its full Git reproduction pin, and the
current publication source. A reproduction commit can match recorded source
bytes without having existed before the measurement. The derivative never
claims a new measurement run or changes an original run identifier.

The reviewed external contract binds an exact finite publication delta and exact
support code. Numerical source, dependencies, corpus inputs, GNN specifications,
claims, receipts and the complete call store retain their authenticated bytes.
Ignored canonical raw inputs are checked against literal pins in the original
source, with the original release inventory retained as supporting evidence.
The separately retained Czech upstream test file is an authenticated archival
artifact: it stays in place and is excluded from measurement and raw replay.
Recognized Lean compiler products must map to pinned source modules; hidden
source, unexpected products and symlinks still fail. The full raw and Lean gates
remain mandatory.
The presentation delta must match exact source transformations. These include
the benchmark paired-interval and word-length legend placements and article-only space reservation
before generated in-context run headings, plus a small article-only gap between
each heading and its table rule. The heading producer retains every recorded
table cell; only the two inserted LaTeX spacing blocks may differ. Figures
reproduce identical numerical artists in separate original/current processes.
The multiplicity forest admits one exact annotation line-break substitution;
its recorded words, values and interval artists remain unchanged. Its corrected
interval also has a deliberate endpoint mutation in the numerical-artist proof,
so a changed interval must fail equality rather than pass as a layout edit.
Exact value-label offsets expose the recorded upper intervals, and exact inset
tick padding separates text from parent-plot caps; only presentation coordinates
change. Numerical comparison includes child axes as well as parent axes,
including the complete benchmark panels and confidence-interval endpoints.
Independent mutations of the original sweep line and a benchmark interval must
both be detected. A directory or path allowlist alone cannot authorize numerical
changes. The statistics and audit-trails supplements each admit one exact
article-only space reservation, before the forest-geometry and word-gate
subsections respectively. Their prose, tokens, citations and table cells must
match the original source after reversing those insertions;
a content mutation still fails even with a matching forged declared hash. The finite
path amendment does not authorize other statistical or scientific edits.

The dashboard and scholarly-presentation refinement admits a separately reviewed,
finite support inventory: the unified dashboard route and browser view, generated
explorer guidance, strict reference-link and typography producers, manuscript
staging, the page-geometry reader, their tests, and the central configuration and
syntax registry. These support files are authenticated individually by the
external review; this does not exempt a directory or authorize model changes.
Additional named manuscript chapters permit exact hash-bound qualitative framing
and descriptive headings, while the authored measurement tokens, original claims,
receipts, cache and numerical model source retain their existing requirements.
The abstract, bibliography and repository Zenodo metadata are also individually
hash-bound support files. Their admission covers the reviewed cognitive framing,
first-mention definitions and verified scholarship; it does not admit new measured
results or reinterpret existing gates. The repository archive description follows
the rendered abstract. The software archive retains its mixed-license notice;
the manuscript deposition has a separate publication metadata payload.
The publication destination in the package URL table, citation file and archive
metadata is the Institute repository. Its availability remains explicitly planned
until the public source is deposited. The package configuration is admitted only
after comparing its parsed TOML against the original measurement source with the
URL table removed from both. Every other field must remain identical, including
dependencies, Python version, build backend, package version and coverage floors.
Refreshed support hashes cannot authorize changes to those fields; deliberate
mutations of each boundary must still fail.
The statistics supplement retains its exact spacing and module-locator repair;
the audit-trail supplement also admits its reviewed first-mention text-to-speech
definition, leaving the quoted historical thresholds intact.
Original-source snapshots execute the original support code;
the current dashboard is an unmeasured interface rather than a new measurement.
The release and final gate must additionally validate actual dashboard behavior,
metadata-derived PDF links and every freshly rendered page after typography
changes. The authored preamble includes one fixed generated typography auxiliary;
its exact config-derived bytes and file presence are checked even after the
template copies the authored preamble over the injected copy. Only that auxiliary
has a dedicated ignore rule. A mandatory post-render manuscript-contract gate
runs after template rendering and before PDF validation, so a successful renderer
exit cannot conceal an unresolved preamble or a missing or altered auxiliary.
Historical approved contracts and packages remain separate evidence.

The current-guidance refinement admits only individually reviewed, hash-bound
documentation support paths. It corrects source locators, gate terminology and
the acquisition-versus-verification boundary without changing measurements.
Measurement-bound model source, including its historical docstrings, retains
its original bytes; current guidance supersedes obsolete comments without
relabeling their measured source identity. The statistics supplement admits its
existing spacing transformation plus one exact module-path correction. Neither
amendment authorizes other source, numerical or scientific changes.

The individual HTML exports resolve visible publication references against the
combined index after template rendering. Strict whole-web acceptance follows
that repair and precedes template provenance validation. The manual rendering
guide is individually hash-bound support. The cache-warming script admits only
exact original-source substitutions in its printed `next_steps` instructions:
select the template provider explicitly, generate portable companions before
rendering, insert the HTML repair and check between template rendering and
validation, and move final acceptance after those manual stages. Capture reconstructs those
substitutions from the original Git bytes and refuses any other script change,
even with a rebound declared hash. Acquisition, budgets, cache handling and
request construction retain their original bytes; the isolated original-source
execution snapshot retains the complete original script.

The offline verifier copies the complete pinned source and regular evidence
files into an isolated execution snapshot, then runs the unchanged original
complete semantic verifier. Its isolated interpreter uses authenticated original
source and audited dependencies. A Python audit policy denies connection,
resolution, datagram and child-process paths before imports. This is a policy
for trusted authenticated Python source and dependencies; it is not an operating
system sandbox for hostile native code. Before/after inventories detect input
mutation. Read-only permissions help prevent accidental writes but do not
protect against an owner deliberately replacing files.

The release controller rehashes the current dependency inventory, interpreter
and virtual-environment configuration through the same isolated collector at
release start, each proof consumption and release finish. Both retained proof
identities must match those actual bytes, and the release interval must retain
one dependency identity. All regular dependency files, including executable
bytecode and files beneath bytecode directories, remain inventoried. Dependency
symlinks fail; isolated no-bytecode-write flags do not exempt readable caches.

The separate live local cache audit runs the original model source against the
authenticated recorded loopback endpoint and weights. It preserves the original
reply-text and aligned-logprob comparison rules and complete-stratum requirement.
It is a live reproducibility check, not a new hosted acquisition. No hosted
credentials or budget overrides enter either derivative step.

A clean full release opts in with `--publication-derivative CONTRACT_PATH`.
Default strict releases retain their strict measurement behavior. Derivative
acceptance requires newly emitted typed offline and live results, a fresh
selfproof, complete execution evidence, independently reviewed support bytes and
unchanged initial/final source and external-input states. A successful process
exit without those artifacts fails acceptance. The release receipt records the
original measurement and current publication identities separately.

Source, declaration and support changes are frozen before source-epoch artifact
regeneration; the subsequent output checkpoint is separate. Existing historical
receipts and failed runs remain preserved. A passing derivative release does not
substitute for independent review of every page of the final PDF or authorize
remote publication.
