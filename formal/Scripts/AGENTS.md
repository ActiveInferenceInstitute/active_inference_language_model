# AGENTS.md — formal/Scripts/

Operating rules for the axiom-report tooling. Quick reference:
[`README.md`](README.md). The axiom policy itself is stated in
[`../README.md`](../README.md) and in `AxiomReport.lean`'s own header, and this file
does not restate either.

## Overview

Two files that turn "the tree compiled" into "the tree compiled and here is exactly
what each declaration trusts". Lean emits a *warning*, not an error, for an
unfinished proof, so a green build proves less than it appears to. The axiom report
is the check that closes that gap.

## Ownership boundary

| Artifact | Owner |
| --- | --- |
| `../axiom_report.txt` | `axiom_report.sh` — its only writer. Never hand-edit it |
| `AxiomReport.lean` | Generated by `scripts/record_formal_claims.py --generate-axiom-script` from `ailm.formal_inventory`; never hand-edit |
| The allowed-axiom policy | `../README.md`, preserved in the generated driver header by `ailm.formal_inventory` |
| Coverage enforcement | `scripts/record_formal_claims.py`, from the repository root |
| The `formal_*` ledger labels | the same recorder |

## Invariants (never violate)

| Invariant | Why |
| --- | --- |
| **This directory stays outside the `AILM/` library root** | `lake build` must not compile the report generator; the report is an explicit, separate step |
| **Every named declaration in `../AILM/` has a `#print axioms` line here** | Missing entries are the failure mode that makes an axiom gate green by construction — a report covering part of the tree reports clean for the rest |
| **The coverage check runs in both directions** | A phantom entry (a report line for a declaration that no longer exists) is refused as well as a missing one |
| **`axiom_report.sh` refuses to write a report with no verdict lines** | An empty report satisfies every downstream check vacuously |
| **A missing or failing `rg` is a tool failure, not vacuity** | Missing `rg` exits 2 before any work; a failing `rg` exits 4 with its status; only a working `rg` finding zero verdict lines exits 3. The prior report is preserved in all three cases |
| **The script never masks a build or Lean failure** | `set -euo pipefail`, and the build runs before the report is written. A stale or truncated report describing a tree that did not compile is worse than none |
| **The incomplete-proof axiom and `Lean.ofReduceBool` never appear in a verdict** | The first means an unfinished proof; the second means some proof started trusting the compiler instead of the kernel |
| **Do not widen the allowed-axiom set** | And do not narrow it past `Classical.choice` either: Lean core's own `Rat.add_comm` reports it, so a stricter policy fails for reasons unrelated to anything proved here |

## File organization

| File | Concern |
| --- | --- |
| `AxiomReport.lean` | `import AILM`, then one `#print axioms` per declaration, grouped by module under `/-! ## AILM.<Module> -/` markers |
| `axiom_report.sh` | Regenerates the driver, builds, stages Lean output, checks verdicts, then replaces `axiom_report.txt`; failures preserve the prior report and print diagnostics |

## Usage

```bash
# From formal/
./Scripts/axiom_report.sh

# Point at a toolchain that is not on PATH
AILM_LAKE=/path/to/lake ./Scripts/axiom_report.sh
AILM_PYTHON=/path/to/python ./Scripts/axiom_report.sh
```

The script `cd`s to `formal/` itself, so it also works when invoked by path from
elsewhere. It exits non-zero when `lake` or `rg` is missing, when the build
fails, when `rg` itself fails, and when the produced report contains no verdicts.

## Adding a declaration

A new theorem in `../AILM/` is discovered recursively. Regenerate the driver and
report together, then record only after both compile and coverage checks pass.
From the repository root:

```bash
(cd formal && ./Scripts/axiom_report.sh)
.venv/bin/python scripts/record_formal_claims.py
```

The recorder refuses if the two sets disagree, naming both the uncovered
declarations and the phantom report entries.
