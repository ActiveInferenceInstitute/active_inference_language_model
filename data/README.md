# data/ — claims and immutable reference-source identity

`publication_sources.json` is a finite archive of historical source blobs, not a
measurement or a copy of development history. Each entry names its exact Git
commit and path, byte extent and SHA-256. It supplies the original package
configuration and the exact source examples needed by provenance controls in a
public checkout without private Git ancestry. The reader in
`ailm._publication_inventory` authenticates the complete archive before parsing
its closed entry set; corrupt, missing, duplicate or unregistered evidence is
rejected. Its source pin and per-entry identities must be independently reviewed
when regenerating it from the named `git show <commit>:<path>` blobs. The normal
full release's original-source materialization remains a separate Git proof.

`claims.json` is the **source of numeric truth** for this entire project. Every
quantitative result in the README, in a docstring, in a design document, in a
figure, and in the manuscript resolves back to an entry there.

`reference_sources.json` serves a different purpose: it is a network-free,
machine-readable snapshot of the exact external PDFs used to ground the
CEREBRUM/case formalism. It preserves Zenodo record metadata separately from
the identity printed inside each deposited PDF, plus filename, byte and page
extent, MD5, SHA-256, download URL, and exact-PDF evidence locators. It is not a
measurement ledger and must not be hydrated as manuscript results.

`widened/` holds the vendored statistics of the widened-observation clause arm
(decision 112): the case-role stream plus one distinguished symbol per verb and
auxiliary, on the same authenticated document partition as the shipped Stage 5
artifact. It is committed so the arm reproduces, and it is here rather than in
`vendor/` for the reason `confirmatory/` is: `vendor/` is the wheel's packaged
runtime surface, held equal to `ailm.resources.RUNTIME_VENDOR_ARTIFACTS` by
`tests/test_wheel_resources.py`. The connected runtime now imports this arm,
so `ailm.resources.RUNTIME_DATA_ARTIFACTS` separately includes its exact bytes
in the wheel without moving its historical source. Its filename-bound digest is recorded in
[`docs/provenance/sources.md`](../docs/provenance/sources.md) and enforced,
together with byte-identical regeneration, by `tests/test_stage5_widened.py`.

`case_word/` holds the case-word (L4→L3) bridge artifact (protocol P3): one
`(word_form, upos, case_label_or_null, label_source)` row per UD English EWT
dev token, split by the same document-index stride as the shipped case
artifact and generated by `scripts/generate_case_word_counts.py` with a
train-only sender map. Its filename-bound digest is recorded in
[`docs/provenance/sources.md`](../docs/provenance/sources.md). Like
`confirmatory/` it retains development-session evidence provenance. The connected
runtime now consumes its train-only sender rows, so `ailm.corpus.case_word`
resolves the canonical source path or the identical installed resource declared
by `ailm.resources.RUNTIME_DATA_ARTIFACTS`. Packaging does not upgrade its
evidential status.

`connected_gum/` preserves the frozen GUM input manifest and local analysis
protocol. `ailm.corpus.connected_gum` authenticates those bytes and the raw test
file before selecting the population. `scripts/record_connected_gum_claims.py`
owns measured outputs and claims; the original registration remains immutable.
The protocol excludes previously inspected documents and fixes observation
access, connection strength, comparator, and document-level uncertainty. It is
a local specification, not external registration or replication.

`literature_search.json` is the bounded evidence record for the related-work
search. It stores exact queries, complete versus blocked retrieval status,
candidate-level inclusion facets, and the policy that forbids a priority claim
while any declared search remains incomplete. The injected search cutoff is
derived from this record, not copied into the free literal registry.

Every file here is read by code, and each has exactly one writer or validator:

| File | Written or validated by | Checked by |
| --- | --- | --- |
| `claims.json` | `scripts/record_*_claims.py` via `ailm.claims.ClaimsLedger.record` | `tests/test_claims_discipline.py`, `tests/test_claims_ledger.py` |
| `figure_alt_text.yaml` | authored; consumed by `scripts/generate_figure_registry.py` | `tests/test_figure_alt_text.py` |
| `learning_agreement.npz` | `scripts/record_learning_claims.py`; read by `src/ailm/figures/learning.py` | `tests/test_learning.py`, `tests/test_figure_provenance.py` |
| `literature_search.json` | authored; read by `src/ailm/manuscript_variables.py` | `tests/test_literature_search.py`, `tests/test_priority_claim_scope.py` |
| `manuscript_literals.yaml` | authored; read by `src/ailm/manuscript_variables.py` | `tests/test_manuscript_variables_contracts.py` |
| `reference_sources.json` | authored after hashing the deposited PDF; verified by `scripts/verify_reference_sources.py` | `tests/test_reference_source_fidelity.py` |
| `registration_provenance.json` | authored; read by `src/ailm/claims.py` and `scripts/assign_claim_status.py` | `tests/test_claims_status.py` |

`tests/test_reference_source_fidelity.py` validates `reference_sources.json`, binds its
source symbols and formulations to `src/ailm/cases.py`, and carries planted
controls for the retired Figure-13 attribution. The normal suite remains
network-free. For an explicit re-check against the official exact-version
records, run the metadata-only or full-file commands documented in
[`docs/provenance/sources.md`](../docs/provenance/sources.md). Update the
snapshot only after inspecting and hashing the exact deposited file; a Zenodo
title or concept DOI alone is not artifact identity.

## Claims-ledger shape

```json
{
  "_schema": "ailm-claims-v2",
  "_description": "Every quantitative claim in README, docstrings, or manuscript must have an entry here linking it to the run that produced it.",
  "claims": {
    "stage1_letter_perplexity": {
      "value": 11.9215,
      "run_id": "stage1_letter_gate",
      "source": "scripts/record_stage1_claims.py",
      "status": "descriptive"
    }
  }
}
```

Three fields per entry are required. `value` is the measurement, `run_id` names the
run that produced it, `source` names the file (or `file::test`) that produced it. A
bare value is not evidence — `tests/test_claims_discipline.py::test_every_ledger_entry_has_provenance`
fails on an entry missing either.

## Epistemic status

The fourth field, `status`, is the schema-v2 answer to "what kind of evidence is
this number?" — optional on write, but `tests/test_claims_status.py` requires every
claim in the committed ledger to carry one of exactly four values:

| Status | Meaning | Assignment rule |
| --- | --- | --- |
| `confirmatory` | An independently time-stamped pre-registration scored under its registered rule | Entry 29 (latent-state G2P learning); the registration commit strictly predates the outcome commit |
| `exploratory` | Test-selected sweeps and diagnostic/subsample arms | The lexical / coupling / clause-to-word sweeps, family-disjoint G2P diagnostic, eval-subsample arms, budgeted-attention probe, and test-owned subset labels |
| `descriptive` | Measured quantities carrying no inferential claim | Counts, sizes, versions, diagnostics, un-registered measurements — and the default for anything ambiguous |
| `analytic` | Closed-form or derived quantities, no sampling involved | Entropy floors, uniform baselines, complexity arithmetic |

Assignment is mechanical, by recorder of origin: `scripts/assign_claim_status.py`
holds the authoritative mapping and reconciles both missing and stale fields
(recorders may also pass `status=` directly). Ambiguity resolves **downward** to `descriptive`,
never up, and the string `confirmatory` may not appear in a recorder whose module
docstring cites no pre-registration decision entry — both directions are enforced
by `tests/test_claims_status.py`. A re-record that names no status inherits the
stored one, so recorder replays never strip the field; reconciliation catches a
stored class that no longer matches the evidence assessment.

Temporal provenance is separate and machine-readable in
`registration_provenance.json`. Plans first written in the same commit as their
executor and outcome are called **prospectively specified in-session**, not
pre-registered, because Git provides no independently timestamped separation.
That distinction downgrades decisions 49 and 73 from `confirmatory` to
`exploratory`; within-session ordering is useful process evidence, but it cannot
substitute for an immutable prior record.

## How a number gets in, and how it gets out

**In** — only through `ailm.claims.ClaimsLedger.record`, called by a recorder in
`scripts/`:

```python
from ailm.claims import load_ledger

ledger = load_ledger(PROJECT_ROOT)
ledger.record("phoneme_count_39", len(CANONICAL_ARPABET),
              run_id="stage0_inventory", source="scripts/record_stage0_claims.py")
```

**Out** — two forms, and they are not interchangeable:

| Where | Form | Resolved by |
| --- | --- | --- |
| `.md` files, `.py` docstrings | `claim:stage1_letter_perplexity` | nothing — it stays literal, and is *checked* by the scanner |
| `docs/manuscript/` | `{{STAGE1_LETTER_PERPLEXITY}}` | `src/ailm/manuscript_variables.py` → `output/data/manuscript_variables.json` |

The token name is mechanically the label uppercased. There is deliberately no second
mapping table to drift out of sync.

## The two invariants a newcomer would otherwise violate

**1. Never hand-edit `claims.json`.** Not to fix a rounding, not to add a label a
document already references, not to make a failing gate green. A hand-typed entry has
a fabricated `run_id` and cannot be re-derived, which defeats the only thing the
ledger is for. Re-run the recorder — and if the recorder produces a different number
than the prose expects, the prose is wrong, not the measurement.

The ledger loader is deliberately conservative about this: unparseable JSON, or a
top-level value that is not an object, raises rather than being replaced, because the
file may hold data the code cannot interpret. Only a *missing* skeleton key is
backfilled, and no existing key is ever overwritten.

**2. Not every manuscript token is a ledger claim.** `manuscript_variables.py` also
emits derived composites and provenance metadata that have **no entry here**:
`STAGE1_UNIGRAM_MARGIN`, `STAGE1_CEILING_SHORTFALL_RATIO`,
`STAGE2_MCNEMAR_TOTAL_DISCORDANT`, `STAGE2_PHONEME_UNIGRAM_MARGIN`, and the whole
`META_*` block, plus a `<LABEL>_RUN` / `<LABEL>_SOURCE` pair per claim. Those work as
`{{TOKEN}}`s in the manuscript, but a `claim:` tag naming one of them in a `.md`
file is an **unbacked** reference and fails the discipline gate. In prose, use only
labels that are actually in `claims["..."]`.

## When the discipline gate fails

```
Unbacked prose claims: ['some_label']
```

Fix by recording the measurement:

```bash
.venv/bin/python scripts/record_stage0_claims.py
.venv/bin/python scripts/record_stage1_claims.py
.venv/bin/python scripts/record_stage2_claims.py
```

**Never by deleting the tag from prose.** That removes the evidence requirement and
leaves the sentence standing.
