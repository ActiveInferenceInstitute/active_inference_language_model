# AGENTS.md — gnn/

Operational contract for this directory. See [`README.md`](README.md) for what
GNN is and why AILM carries specs; [`SPEC.md`](SPEC.md) for the enforced subset.

---

## What these files are

**A GNN spec is a declarative source of truth for model STRUCTURE.** It states
the state space, the dimensions, the semantic role of every matrix, the
structural form of each parameter block, and the provenance of anything learned.

It is not a source of truth for:

- learned probabilities (those live in `vendor/`, regenerated by their generator);
- measured results (those live in `data/claims.json`, recorded from real runs);
- prose explanation (that lives in `docs/` and the module docstrings).

---

## The one rule that matters

> **Never edit a spec to make a conformance test pass.**

`tests/test_gnn_conformance.py` compares the spec to a LIVE pymdp agent. When it
fails, exactly one of two things is true, and you must decide which on the
evidence before touching anything:

| Situation | What to fix |
|---|---|
| The code changed intentionally — a new alphabet size, a new modality, a genuinely different emission | The **spec**. Update the dimensions, the ontology and `ModelParameters` together, in one commit, with the reason in the commit message. |
| The code changed by accident — a transposed matrix, a matrix in the wrong slot, a prior that is no longer what it was declared to be | The **code**. This is the case the specs exist to catch. |

Editing the spec in the second case does not fix anything: it deletes the alarm
and leaves the fire. It is the same failure mode as deleting a `claim:` tag to
make the claims scanner green, and it is prohibited for the same reason.

If you genuinely cannot tell which side is wrong, that is a signal to go measure:
run the oracle cross-check (`tests/test_oracle.py`) and the relevant stage gate.
A wiring defect shows up there as a *number*, and the number decides.

## Invariants

| Invariant | Why |
|---|---|
| Every declared variable has an `ActInfOntologyAnnotation` entry | An un-annotated slot is a slot whose role nothing pins — the parser rejects it |
| `A=RecognitionMatrix`, `B=TransitionMatrix`, `D=Prior` on every level | These three names are the guard; without them the spec is decoration |
| Learned matrices are **never inlined** | A copy of a derived artifact is a second source of truth that drifts. The parser rejects `{...}` matrix literals |
| `InitialParameterization` names the generator AND the artifact for anything learned | Provenance must be reproducible, not remembered |
| `ModelParameters` carries `num_hidden_states` and `num_obs` matching the code | This is what rejects a transposed emission |
| Section names come from the canonical thirteen | A misspelled section would silently drop the whole block, so it is an error |
| `src/ailm/gnn/` imports nothing beyond stdlib and numpy | An auditor that shares code with what it audits inherits the flaw it audits for. Upstream GNN's 25-step pipeline must never become an AILM runtime dependency |

## Changing a level

1. Change the code in `src/ailm/levels/`.
2. Run `tests/test_gnn_conformance.py`. It will fail, and the violation text will
   name every slot that moved.
3. Update the spec to match — dimensions, ontology, `ModelParameters`, and the
   structural forms — and say in the commit message what changed and why.
4. Re-run the conformance test **and** the level's gate test. Conformance says the
   shape is right; only the gate says the model is any good.
5. If the level gained a factor, a modality or real controls, read
   [`SPEC.md`](SPEC.md) first. Conformance checks the declared action axis,
   policy dimensions and supplied inference configuration; extend the live
   binding and add a failing control for the new layout. Structural arrays and
   policy precision must remain finite.

## Adding a level

Copy the closest existing spec, keep the section order, and add the file to the
appropriate inventories and live-Agent fixture in
`tests/test_gnn_conformance.py`. `TestEveryShippedSpecIsCovered` requires the
covered set to equal every canonical spec discovered under `gnn/models/`, with
no exception list, so a spec added without a live binding and a binding whose
file does not exist both fail. Add the corresponding bit-identity construction
case to `tests/test_spec_agent.py`; conformance and spec-built identity answer
different questions, and a new canonical spec must satisfy both.

New levels must also add a positive control. A conformance test with no control
proving the checker can reject the new level's specific mis-wiring is a test that
measures nothing about it.

## What not to do

- **Never** widen the accepted section vocabulary to make a file parse. Fix the
  file.
- **Never** relax `_STRUCTURAL_TOL` in `src/ailm/gnn/types.py` to absorb a failing
  identity or uniformity check. A structural form either holds or the model
  changed.
- **Never** report conformance as evidence that a probability, a perplexity or an
  accuracy is correct. It checks structure and declared roles, nothing else.
  Overstating its scope is the one way this directory could make AILM *less*
  trustworthy rather than more.
- **Never** vendor the upstream GNN pipeline into this repository to "make
  interoperability testable". The interop test is opt-in and skips cleanly by
  design.
